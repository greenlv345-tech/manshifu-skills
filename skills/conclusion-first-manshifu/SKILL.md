# 结论先行表达 — 从读者视角出发的写作原则

> 拆自小马宋《营销笔记》的写作结构和"顾客视角"核心原则。

## R (Reading) — 原文精髓

小马宋《营销笔记》全书35篇笔记，每一篇都遵循同一个结构：先给出核心结论，再展开论证。典型如：

> "营销是大力士，但它不是神，过度相信营销，就等于相信一种方法论的迷信。"
> — 笔记1 开篇第一句

> "营销的本质是利他，是成就他人，是创造价值，企业的利润只是因创造价值而获得的奖励。"
> — 笔记5 开篇

> "一个问题的解决，总是依赖于与问题相邻的更高一级的问题的解决。"
> — 自序（引魏斯曼）

> "你熟悉你的餐厅，但顾客不熟悉，你要从顾客的视角去思考问题。你的审美品位不是顾客的审美品位，你的思考角度也未必是顾客的思考角度。"
> — 自序

## I (Interpretation) — 方法论骨架

结论先行不是"把最后一段搬到第一段"这么简单。它是一套**从读者视角出发的写作操作系统**：

1. **读者没有耐心读你的推理过程**
   读者心里只有一个问题："这跟我有什么关系？"如果你前三段都在铺垫背景、介绍概念，读者已经划走了。结论先行 = 你先把答案亮出来，"这就是我的观点，你如果不信，我接下来用证据说服你"。

2. **结论先行反向逼迫作者想清楚**
   小马宋说"一个问题的解决总是依赖于与问题相邻的更高一级问题的解决"。写不出结论先行的版本，往往是因为作者自己也没想清楚到底要说什么。当你被逼着用一句话讲清楚核心观点，模糊的思维就无处遁形。

3. **结论 ≠ 标题党**
   结论先行的"结论"不是夸张的广告语，而是对文章核心论点的**诚实浓缩**。就像小马宋的书名——《营销笔记》——朴实但准确。每篇笔记的加粗首句，不是"惊人发现！90%的人不知道的秘密"，而是"营销是大力士，但它不是神"。

4. **"顾客视角"在写作中的映射**
   小马宋反复强调：不能基于自己的视角，要基于顾客的视角。对应到写作：
   - 作者的视角：我想讲A→B→C→D的逻辑推导
   - 读者的视角：你直接告诉我D，然后我需要的话看你为什么推出D
   - 结论先行 = 优先满足读者的视角

## A1 (Past Application) — 书中案例

**全书本身就是结论先行的范本**：每篇笔记结构如下：
1. **加粗标题** = 核心结论
2. **开篇一段** = 用场景/故事引出问题
3. **主体** = 案例展开 + 逻辑分析
4. **结尾** = 回扣核心结论，提炼行动启示

比如笔记1《理解营销，从放弃营销的幻觉开始》：
- 结论：营销不是神，不要相信一招制胜
- 故事：江小白的表达瓶 = 简单归因的陷阱
- 展开：江小白成功背后有200万销售点、10年行业经验的渠道能力
- 升华：巴菲特"人们不愿意慢慢变富"

**包装设计中的"结论先行"**：云耕物作包装上最突出的就是一个巨大的"暖"字——这就是"结论先行"在视觉设计中的映射。顾客不需要读完所有产品说明才知道这款红糖姜茶的特点，一个"暖"字，秒懂。

## A2 (Future Trigger) — 何时调用

用户说以下内容时自动触发本技能：
- "帮我改成结论先行"
- "把结论放前面"
- "这段话的重点是什么"
- "帮我重写，让它更直接"
- "结论先行改写"
- "提炼核心观点放在前面"
- 任何需要提升表达效率和说服力的写作场景

## E (Execution) — 结论先行四步法

### 第一步：逼出核心结论

对原文回答三个问题：
1. 如果读者只能记住一句话，你希望他记住什么？
2. 这句话能不能独立成立？（不需要上下文也能理解）
3. 这句话是不是"诚实"的？（不是夸大、不是标题党）

用以下模板写出核心结论句：
> **[主论点]**, 因为/所以 **[最关键的一个理由或含义]**。

示例：
- ❌ "今天我们来聊聊用户增长"（这是主题，不是结论）
- ✅ "用户增长的核心不是拉新，而是留存——因为每一个流失的用户都在消耗你的拉新成本。"（这是结论）

### 第二步：以结论为核心重组开头

格式：
```
【结论句】← 直接丢出来，不要铺垫

【为什么这个结论重要】← 用一句话说明读者为什么要关心

【我怎么得出这个结论的】← 证据/案例/逻辑（选最有说服力的1-2个前置）
```

### 第三步：用"读者测试"检验

- 遮住文章的标题和开头，只看核心结论句，一个完全不了解背景的读者能理解吗？
- 如果第一个读者反应是"什么意思？"，说明结论还不够直接
- 如果第一个读者反应是"哦，原来如此"或"那又怎样？"，说明结论还不够有力

### 第四步：全文回改

- 每一段的主题句也要遵循"结论先行"（段落首句 = 该段的核心观点）
- 段落之间要有"结论→解释→案例→回扣"的微循环
- 删掉所有"铺垫性废话"（"众所周知""在当今社会""随着时代的发展"...）

## P (Post-Processing) — 保存成品

完成改写后，可保存到你的笔记系统（如 Get 笔记、Notion、飞书文档），标题建议格式为 `[结论先行] {原标题}`，方便后续检索和迭代。

> 如果用户只要求口头改写、不需要产出文件，则跳过此步骤。

## B (Boundary) — 什么情况下不适用

1. **悬念驱动的叙事**：小说、特稿报道、某些需要在结尾揭晓答案的故事，结论先行会破坏阅读体验
2. **悬念式教学**：某些教学内容需要先引导读者思考、困惑，再给出答案，效果更好
3. **负面/坏消息传达**：需要铺垫同理心和背景，直接丢结论会显得冷酷
4. **高度技术性的推导过程**：如果读者需要跟随每一步推导才能理解结论，结论先行会让他们"知其然不知其所以然"
5. **对话/回应场景**：在日常对话中，结论先行可能显得过于生硬
